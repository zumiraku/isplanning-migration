# モジュール 5件 — 貼り付けパッケージ

貼り付け先: クリエイターモード › **モジュール管理**

## 重要な訂正

当初 `<{include file="…"}>` で部品を読む前提でテンプレートを書いていました。
**それは動きません。** モジュール管理の画面が答えでした ── メイクショップは
`$module.<名前>` という独自の参照方式を持っており、`モジュールタグ` の列に
そのまま表示されています。

既存で6件入っています。

```
フッター              $module.footer
ヘッダー              $module.header
サイドメニュー        $module.side_bar
バナーエリア          $module.banner_area
最近チェックした商品  $module.checked
商品グループ表示      $module.group
```

**下2つは移行の答えでもありました。** ベーシックモードの `[BRANDGROUP]` は
`$module.group`、最近チェックした商品は `$module.checked` です。商品詳細
テンプレートは、この2つを使う形に直しました。

## 登録するもの

| ファイル | モジュール名 | 上書き / 新規 |
|---|---|---|
| `header.tpl` | ヘッダー | **既存を上書き** |
| `footer.tpl` | フッター | **既存を上書き** |
| `category_tiles.tpl` | category_tiles | 新規（「モジュール追加」） |
| `category_captions.tpl` | category_captions | 新規（「モジュール追加」） |
| `category_title.tpl` | category_title | 新規（「モジュール追加」） |

新規3件の名前は `category_tiles` `category_captions` `category_title` としてください。
`side_bar` `banner_area` と snake_case なので、それに合わせています。
テンプレート側は `<{$module.category_tiles}>` で参照しています。

## なぜヘッダーとフッターをモジュールにしたか

最初は11ページそれぞれに直接書いていました。**同じ100行が11回**あることに
なり、電話番号を1つ直すのに11ファイルを開くことになります。モジュールに
出したことで、ページテンプレートの合計が約1,300行減りました。

## 順番

**モジュールが先です。** ページテンプレートは `<{$module.category_tiles}>` を
参照するので、モジュールが無い状態でページを貼ると、その部分が空になります。

1. `header.tpl` → 既存「ヘッダー」を開いて全選択・置き換え
2. `footer.tpl` → 既存「フッター」を開いて全選択・置き換え
3. 「モジュール追加」→ `category_tiles`
4. 「モジュール追加」→ `category_captions`
5. 「モジュール追加」→ `category_title`（86KBあります。時間がかかります）

## サイドメニューについて

`$module.side_bar` は使いません。ベーシックモードの左サイドバーは畳んで、
中身をフッターとヘッダーのカテゴリメニューに移しています。スマホで画面の
横幅を固定列に使うのは、この案件の趣旨に合わないためです。

ただし畳んだだけでは6ページが到達不能になっていたので、フッターに導線を
置いてあります（`footer.tpl` の「粗品の選び方」）。

## category_title だけ、なぜ86KBもあるのか

カテゴリページのタイトル**605件**が、そのまま入っているからです。

クリエイターモードでは「カテゴリ設定」の独自タイトル欄が無くなります。
13年かけて手で書かれた607件が、切替と同時に全部消えます。

当初は法則から作り直す計画で、いちばん当てはまる法則でも607件中294件でした。
ただ、手元の2つのファイルが同じ旧URLで突き合わせられることに気づきました。

```
inventory/categories-seo-backup.csv   旧URL → 移行前のタイトルそのもの
package/url-bulk/categories-url.csv   旧URL → 新しいct番号
```

つまり **ct番号ごとの正解が分かっている**ので、法則で近づける必要がありません。
605件を一字一句そのまま出しています。`tools/check-category-titles.sh` が
生成物を読み直して1件ずつ元データと照合し、605件全一致を確認済みです。

### ページ本体に入れなかった理由

これまでに貼り付けが通った最大のモジュールは category_captions の10KBです。
86KBはその8倍で、通る保証がありません。

これを `category.tpl` に入れてしまうと、**カテゴリページそのもの**――606URL、
商品一覧、ページャ、タイル――が、その1点に道連れになります。モジュールに
分けておけば、仮に86KBが弾かれても失うのはタイトルだけで、ページは出ます。

### 貼り付けが弾かれたら

そのときは連絡をください。法則で組み立てる短い版に切り替えます。
605件が294件相当に減りますが、ページは無事です。

## 直せなかったタイトルが2件あります

`inventory/category-titles-report.csv` に理由付きで出しています。

- **ct668** — 現行サイトのタイトルが `■■■` です。そのまま復元すると不具合を
  復元することになるので、表から外してパンくずから組み立てる方に回しました。
- **/shopbrand/all_items/** — 「すべての商品」。ct番号が振られていません。
  カテゴリではないので対象外です。URL対応表で1件だけ対応が取れなかったのも
  これで、**カテゴリが1件行方不明だったわけではありません。**
