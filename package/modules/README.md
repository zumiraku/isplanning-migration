# モジュール 5件 — 貼り付けパッケージ

貼り付け先: クリエイターモード › **モジュール管理**

## 重要な訂正

当初 `<{include file="…"}>` で部品を読む前提でテンプレートを書いていました。
**それは動きません。** モジュール管理の画面が答えでした ── メイクショップは
`$module.<名前>` という独自の参照方式を持っており、`モジュールタグ` の列に
そのまま表示されています。

既存で6件入っています。

```
フッター              $module.footer
ヘッダー              $module.header
サイドメニュー        $module.side_bar
バナーエリア          $module.banner_area
最近チェックした商品  $module.checked
商品グループ表示      $module.group
```

**下2つは移行の答えでもありました。** ベーシックモードの `[BRANDGROUP]` は
`$module.group`、最近チェックした商品は `$module.checked` です。商品詳細
テンプレートは、この2つを使う形に直しました。

## 登録するもの

## なぜヘッダーとフッターをモジュールにしたか

最初は11ページそれぞれに直接書いていました。**同じ100行が11回**あることに
なり、電話番号を1つ直すのに11ファイルを開くことになります。モジュールに
出したことで、ページテンプレートの合計が約1,300行減りました。

## モジュール管理までの行き方

`https://console.makeshop.jp/design/editor?shopId=isplanning` を開きます。

すでにクリエイターモード編集画面に入っている場合、左の濃い列に「編集中の
デザインセット 発見マーケット_移行版」と出ています。**その状態なら
「クリエイターモード編集画面へ ›」を押す段はありません。**（濃い帯の文字は
「ベーシックモード適用中」のままです。これは適用中のモードの表示であって、
いま編集している場所の表示ではありません）

左の濃い列は `全ページ共通 / トップ / 商品カテゴリー / 商品検索結果 /
商品詳細 / 商品レビュー一覧 / 商品レビュー投稿` …と並んでいますが、
**モジュール管理は初期表示では画面に映っていません。** 列の上にポインタを
置いてホイールを下に回すと出てきます。

## 順番

**モジュールが先です。** ページテンプレートは `<{$module.category_tiles}>` を
参照するので、モジュールが無い状態でページを貼ると、その部分が空になります。

1. `header.tpl` → 既存「ヘッダー」を開いて全選択・置き換え
2. `footer.tpl` → 既存「フッター」を開いて全選択・置き換え
3. 「モジュール追加」→ `category_tiles`
4. 「モジュール追加」→ `category_captions`
5. 「モジュール追加」→ `category_calendar`

## サイドメニューについて

`$module.side_bar` は使いません。ベーシックモードの左サイドバーは畳んで、
中身をフッターとヘッダーのカテゴリメニューに移しています。スマホで画面の
横幅を固定列に使うのは、この案件の趣旨に合わないためです。

ただし畳んだだけでは6ページが到達不能になっていたので、フッターに導線を
置いてあります（`footer.tpl` の「粗品の選び方」）。

## category_title は不要になりました

クリエイターモードでも `$page.title` がカテゴリ独自タイトルをそのまま返すことが
実サイトで確認できました（2026-09-05）。**カテゴリのタイトルも説明文も、最初から
失われていません。** 86KBの表は `contingency/` に移してあります。理由と、戻し方は
`contingency/README.md` にあります。

**すでにモジュールを登録済みの場合は、モジュール管理から削除してください。**
`category.tpl` は `<title><{$page.title}></title>` を使う形に戻してあります。

## category_calendar — ct646（卓上カレンダー）だけのもの

`/shopbrand/051/O/` ＝ **ct646** です。C28 が53本のカテゴリ別テンプレートを
「52本は共通テンプレート＋データ、**ct646だけが例外**」と整理した、その1本。

営業日カレンダー2か月分が、**カテゴリ設定のフリースペース**に手組みで
入っていました。

### なぜモジュールなのか

**クリエイターモードには、カテゴリのフリースペースを出すタグがありません。**
公式リファレンスから取った754タグに該当がなく、受け皿が存在しません。
放っておくと、この1カテゴリだけ内容が消えます。

`category.tpl` が `<{if $category.code == 'ct646'}>` で呼びます。他の606件の
カテゴリでは出ません。

### 毎月の更新について

カレンダーは2か月分を直に書いた表です。**月が変われば更新が要ります。**
移行で増えた手間ではなく、いまも同じことをされています。

モジュールに分けたのはそのためです。更新はこの1件を開いて `<h3>` と表を
直すだけで、カテゴリページのテンプレート（270行）を貼り直す必要はありません。

休業日のセルには `class="is-closed"` を付けます。セルの中に読み上げ用の
文字も入れてあります。**色だけで休業日を示すと、色の見分けがつかない方に
伝わりません。** 消さないでください。

### 商品25枚は持ってきていません

元のフリースペースには、卓上カレンダー商品を25枚並べた表もありました。
価格を直書きした写しなので、**価格改定や品切れのたびに実際と食い違います。**

カテゴリページ本体が `$category.item.list` で実際の商品を、実際の価格と
在庫で出します。手組みの写しを抱えるより正確です。
