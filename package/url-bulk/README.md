# URL一括設定 — アップロード用CSV 3本

生成: `sh tools/build-url-csv.sh` / `-products.sh` / `-categories.sh`

| ファイル | 件数 | 対象 |
|---|---:|---|
| `products-url.csv` | **9,513** | 商品 `/shopdetail/…` → `/view/item/…` |
| `categories-url.csv` | **606** | カテゴリ `/shopbrand/…` → `/view/category/ctNNN` |
| `freepages-url.csv` | **82** | フリーページ `/html/…` → `/view/page/…` |
| **合計** | **10,201** | |

これが通れば、**移行前のURLがそのまま生き続けます。** 外部サイトからのリンクも、
13年分の検索評価も途切れません。

## 🔴 切替後にしか投入できません

フリーページ82件で試したところ、全件が
「フリーページのデザインセット情報が取得できませんでした」で失敗しました。
システムURLは編集画面の表示と完全一致していたので、形式の問題ではありません。
**この機能は適用中のデザインセットしか見ません。**

したがって順序はこうなります。

```
ショップに適用 → 旧URLが404になる → CSVを3本投入 → 復旧
```

その隙間の長さが、作業する人の手の速さで決まります。手順は
[docs/cutover-runbook.md](../../docs/cutover-runbook.md) にまとめました。

## 検証済み

- 3本とも UTF-8 BOM 付き（ダウンロードされた雛形に合わせています）
- 形式不正 **0件**
- システムURLの重複 **0件**
- 追加URLの重複 **0件**（3本を通しで確認）
- 最大件数 20,000 / 最大 2MB の制限内（最大は商品の 675KB）

## 各列の値

| 列 | 商品 | カテゴリ | フリーページ |
|---|---|---|---|
| URLタイプ | 1 | 2 | 4 |
| システムURL | `/view/item/<コード>` | `/view/category/ctNNN` | `/view/page/pageNN.html` |
| 名称 | 商品コード | カテゴリ名 | ページ名 |
| canonical属性 | 0 | 0 | 0 |
| 追加URL | `/shopdetail/<コード>/` | `/shopbrand/…` | `/html/pageNN.html` |
| noindex設定 | 0 | 0 | 0 |

**canonical を 0 にしている**のは、移行後に残るのが `/view/…` 側だからです。
1 にすると、いずれ捨てるURLを「正」だと検索エンジンに宣言することになります。

**商品の名称にコードを入れている**のは、9,514件分の商品名が手元にないからです。
この欄は管理用で公開されません。空にして必須だった場合、9,513行が一度に
落ちます。フリーページで82件が全滅したときのように原因の切り分けに時間を
取られるより、確実に埋まる値を入れておく判断です。

## カテゴリのコード対応について

商品はコードが同じなので機械的ですが、**カテゴリは旧新でコード体系が違います**。

```
旧  /shopbrand/003/001/X/
新  /view/category/ct5
```

対応表の出どころは、クロール時に各カテゴリページが持っていた
`rel="alternate"` です。スマホ版URLに `category_code=ctNNN` が入っていました。
**SPサイトは移行で消えますが、消える前に記録していたおかげで対応が取れます。**

607件中606件。取れなかった1件は `rel="alternate"` を持たないページで、CSVには
含めていません。推測でct番号を当てると、**別のカテゴリのURLを別のカテゴリに
割り当てる**ことになります。

## 対象外

**お知らせ100件**。URLタイプに該当する値がありません。新URLが
`/view/news/yymmddhhmmss` という日時形式で、旧URLから機械的に導けないため、
仮に機能が対応していても対応表が作れません。13年分の被リンクがあります。
