# 🔴 URL一括設定のCSVが、公式仕様と3列ずれています — 2026-09-08

公式マニュアル https://ms-manual.makeshop.jp/originalurl/ を読みました。
**読むのが遅すぎました。** これまで「マニュアルの列」として記録していたのは
列名だけで、各列の入力ルールを読んでいませんでした。

## 1. アップロードの上限は 200KB です（2MB ではありません）

> 5. CSVで一括設定できるURL数に制限はありませんが、
>    **アップロードファイルの最大サイズは200kbまで**となっています。

こちらの記録には「上限 2MB / 20,000件」と書いてありました。出どころ不明です。

| ファイル | サイズ | 200KB に対して |
|---|---:|---|
| `products-url.csv` | **661KB** | **3.3倍。弾かれます** |
| `categories-url.csv` | 65KB | OK |
| `freepages-url.csv` | 11KB | OK |
| `news-url.csv` | 13KB | OK |
| `pagetypes-url.csv` | 0.2KB | OK |

商品は最低4分割が要ります。**当日いきなり弾かれるところでした。**

## 2. 「システムURL」はプラットフォーム側のURLです

マニュアルの例と、こちらが作ったもの:

```
マニュアル  1,/shopdetail/001001000028/ ,商品名,   1,/product-1-1,0
            2,/shopbrand/ct1            ,カテゴリ名,1,/category-4-1,0
            3,/html/page1.html
            4,/view/page/ページ名

こちら      1,/view/item/000000003919   ,"000000003919",0,/shopdetail/000000003919/,0
            2,/view/category/ct640       ,"イベント…",   0,/shopbrand/001/O/,0
```

**B列とE列が入れ替わっています。** こちらは「新URLをシステムURLに、旧URLを
任意URLに」と組みました。マニュアルはその逆で、システムURLは**プラット
フォームが採番した側**、任意URLは**こちらが付けたい別名**です。

## 3. 「名称」は変更不可です

> 3 C 名称 必須 システムより入力 ・**変更不可**
> 商品名、カテゴリ名、独自ページ名称のいずれかが、システムにより入力されます。

こちらは商品コードやカテゴリ名を自前で入れています。

## 4. 🔴 そして、旧URLは任意URLに指定できません

> ※2 重複するURLとは …**システム使用済みURL（※以下参照）も使用できません。**
>
> システム使用済みURL
> `/html`（ショップ情報関連ページ） `/shop`（ショップ機能関連）
> `/new`（お知らせ） `/shopbrand`（商品カテゴリー）
> `/shopdetail/12桁の数字`（商品詳細） `/view`（クリエイターモード共通）
> **上記ディレクトリ以下にあるページのURL**、および `/index.html`

こちらが任意URLに入れているのは、**そのリストの全部**です。

```
/shopdetail/000000003919/    ← 禁止
/shopbrand/001/O/            ← 禁止
/html/page9.html             ← 禁止
```

つまり **「旧URLを任意URLとして生かして404を防ぐ」という移行計画の中心が、
この機能では成立しません。**

## 何を取り違えたか

この機能は「他社からの移行の際、他社で利用していたURLと同じURLを再現する」
「商品名をURLに入れて検索にヒットしやすくする」ためのものだと、マニュアルの
効果欄に書いてあります。**きれいなURLを新しく足す機能**であって、**旧URLを
生かし続ける機能ではありません。**

以前アップロードを試したとき「デザインセット情報が取得できませんでした」で
82件すべて失敗しました。**あれを「切替前だから」とだけ解釈して、内容の妥当性を
確かめずに先へ進みました。** 形式が違っていても同じ失敗の出方をします。

## 決着させる方法は1つです

URL一括設定の画面には**現在のURL情報をCSVで書き出す**機能があります。

> 初回は、項目「任意URL」の値は、ブランクとなっています。
> 「任意URL」、「canonical属性の設定先」の値を適宜変更してください。

**正しい使い方は「落として、2列だけ書き換えて、戻す」** です。
落としたファイルを見れば、この店舗のシステムURLが `/shopdetail/…` なのか
`/view/item/…` なのか、名称に何が入るのか、**推測なしで分かります。**

そして、それが分かるまで切替を実行してはいけません。

## いま確かなこと・不確かなこと

| | |
|---|---|
| 確か | 200KBの上限。商品CSVは分割が要る |
| 確か | 名称は変更不可 |
| 確か | `/shopdetail/` `/shopbrand/` `/html/` は任意URLに使えない |
| **不確か** | **切替後、商品の「システムURL」が `/shopdetail/…` のままなのか `/view/item/…` になるのか** |

最後の1点が決定的です。**`/shopdetail/…` のままなら、そもそも商品URLは
変わらず、この機能を使う必要すらありません。** 逆に `/view/item/…` に
変わるなら、旧URLは任意URLに指定できないので、別の手段（サーバー側の
リダイレクト、あるいは受け入れ）を考えることになります。
