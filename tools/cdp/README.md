# tools/cdp — 管理画面をこちらから操作する道具

貼り付けと確認を人手でやると、**押した／押していない、見た／見ていない**の
区別がつきません。実際に2巡むだにしました。ここにある道具は、

  流し込む → 保存 → **読み直す** → 突き合わせる

を毎回やります。「保存を押した」では終わりにしません。

## 使う前に

```
node tools/cdp/launch.js      ログイン済みのChromeを操作できる状態で立てる
node tools/cdp/probe.js       …ではなく、まず probe ではなく下の順で
```

`launch.js` はChromeをいったん閉じます。**開いているタブは失われます。**

- Chrome 136 から、既定のプロファイルでは `--remote-debugging-port` が
  **黙って無視されます。** 別の場所に写したプロファイルで立てます。
- 写すのは `Local State` / `Cookies` / `Preferences` だけです。
  パスワードの保管庫（Login Data）には触れません。
- 管理画面のログインは**人が入れます。** パスワードは扱いません。

## 道具

| | |
|---|---|
| `launch.js` | 操作できるChromeを立てる |
| `probe-desc.js` `probe.js` | 商品詳細に一時的な印を入れて実データを読む（読んだら戻す） |
| `paste.js` | 1ページ種別を流し込んで保存し、読み直して突き合わせる |
| `paste-all.js` | 全ページ共通＋11ページ種別をまとめて |
| `modules.js` | モジュール6件（IDの確認と書き込み） |
| `preview.js` | 「プレビュー」を押して、配信されるHTMLを保存する |
| `verify.js` | 配信されたHTMLを点検する |
| `parity.js` | 現行サイトの文言が出ているかを突き合わせる |
| `diff.js` `module-diff.js` | 保存されている中身と手元のファイルの差を見る |
| `goto.js` `eval.js` `open.js` | 画面を開く・式を評価する（下調べ用） |

## つまずいたところ

**プレビューのURLを開くだけでは古いものが返ります。** HTMLは
`プレビュー` ボタンを押した瞬間に焼き付けられます。`preview.js` は毎回押します。

**プレビューは「保存済みの内容」を描きます。** `formPreview` に流し込んだ
HTMLは使われません（印が1つも出ませんでした）。`probe.js` は
いったん保存 → 読む → **元に戻す** の順でやります。

**ポップアップは開きません。** 人が押していないフォーム送信なので止められます。
`target` を `_self` にしてから押します。送る中身は変わりません。

**モジュールの中からモジュールは呼べません。** `<{$module.calendar1}>` を
左メニュー（モジュール）の中に書いても展開されません。エラーも出ません。

**保存の入口は画面ごとに違います。**

```
ページ種別  g_editor_object["html_pc"]   →  saveContent()
モジュール  textarea[name=content] の CodeMirror  →  updateModule()
```

**文字数だけで一致を判断できません。** サーバーは保存時に一部の文字を
数値参照にします（`—`→`&#8212;`、`🔴`→`&#128308;`）。しかも元ファイル自体が
`&#12316;` `&#169;` を持っています。**両側に同じ処理をかけてから**比べます。

## 🔴 タブを1つ閉じると、Chrome ごと終わります（2026-09-09）

`/json/close/<id>` で最後のページを閉じたら、Chrome が終了しました。
そして **管理画面のセッションはセッションCookie** なので、
ブラウザが終わった時点で消えます。立て直しても `/login` に飛ばされます。

```
/json/close/<最後のタブ>  →  Chrome 終了  →  ログイン状態が消える
```

新しいタブが要るときは、**先に作ってから**閉じてください。
`/json/new` は `PUT` です（`GET` だと "Using unsafe HTTP verb" と言われます）。

### launch.js は既定で作り直しません

以前は毎回 `%TEMP%/isp-cdp-profile` を**消してから**既定プロファイルを
写していました。ところが管理画面にログインしたのは**その一時プロファイル
の中**です。消せばログインごと消えます。

```
node tools/cdp/launch.js            そのまま使う（ログインを保つ）
node tools/cdp/launch.js --fresh    作り直す（ログインし直しが要ります）
```

## 🔴 CDPスクリプトを2本同時に走らせないこと

`page()` は**最初のページtargetを取ります**。2本走らせると同じタブを
取り合い、片方の測定が他方の画面を測ります。実際、`sp-preview` の最中に
`paste.js` を回して、**お知らせ詳細と利用案内の2行が嘘の値**になりました
（横幅 981/980・未展開タグあり）。単独で回せば両方とも正常です。

## 🔴 出力を `| tail` や `| head` に通さないこと

途中経過が一切見えなくなり、「止まっている」と誤診します。実際に
`js-audit.js | tail -n 12` を10分以上「固まっている」と判断して
止めましたが、**ただの緩衝でした。** ファイルに落として `cat` します。

```
node tools/cdp/js-audit.js > "$TEMP/js-audit.log" 2>&1
```

## 🔴 トップと会員制は、プレビューURLが同じです

```
トップ            https://www.isp-sp.com/?ptk=…
会員制・年齢確認   https://www.isp-sp.com/?ptk=…   ← 同じ
```

**会員制（page_type=19）を一度プレビューすると、以後トップのプレビューが
会員制ページを返すようになりました。** 本文52文字（著作権表示だけ）です。

- 時系列が合います。19を一度も出していない実行では、トップは 7,789字 ○
- 保存されているHTMLは 14,495文字のまま（＝テンプレートは無事）
- `preview.js` が取った `top.html` は 90,565字で、167項目に通っています
- 本番（ベーシック）のトップにゲートはありません（実測・ヘッダーあり）
- 2026-09-08 にクリエイターモードで公開したとき、トップは正常に出ていました
  （山口様のご指摘21件にトップの中身の話が複数あります。真っ白なら成立しません）

### 決着しました — 直し方は「保存」です（2026-09-10 00:45 JST）

**別セッションでも直りませんでした。** ログインし直して、会員制を一度も
出していない状態でトップをプレビューしても、ゲートページのままでした。
`ptk` はログインしても変わりません（`45bdf24e…`）。**セッションではなく
デザインセットに紐づいた値**だからです。

効いたのは**保存**でした。

```
node tools/cdp/paste.js top package/templates/top.tpl html   ← 保存し直す
node tools/cdp/preview.js top                                 → 90,255文字 ○
```

プレビューは**保存済みの内容**を描きます。会員制（19）を出すと、パス `/` の
描画が19の保存内容に置き換わります。**プレビューを押し直しても戻りません。
page_type=2 を保存し直すと戻ります。**

箱の中身は最初から無事でした（14,482文字。保存前・保存後とも一致）。
**壊れていたのはプラットフォーム側の描画の割り当てだけ**です。

⚠️ 会員制（19）をプレビューしたら、**そのあとトップを保存し直してください。**
   `sp-preview.js` は既定で19を出しません（出したら最後に保存が要ります）。
