# tools/cdp — 管理画面をこちらから操作する道具

貼り付けと確認を人手でやると、**押した／押していない、見た／見ていない**の
区別がつきません。実際に2巡むだにしました。ここにある道具は、

  流し込む → 保存 → **読み直す** → 突き合わせる

を毎回やります。「保存を押した」では終わりにしません。

## 使う前に

```
node tools/cdp/launch.js      ログイン済みのChromeを操作できる状態で立てる
node tools/cdp/probe.js       …ではなく、まず probe ではなく下の順で
```

`launch.js` はChromeをいったん閉じます。**開いているタブは失われます。**

- Chrome 136 から、既定のプロファイルでは `--remote-debugging-port` が
  **黙って無視されます。** 別の場所に写したプロファイルで立てます。
- 写すのは `Local State` / `Cookies` / `Preferences` だけです。
  パスワードの保管庫（Login Data）には触れません。
- 管理画面のログインは**人が入れます。** パスワードは扱いません。

## 道具

| | |
|---|---|
| `launch.js` | 操作できるChromeを立てる |
| `probe-desc.js` `probe.js` | 商品詳細に一時的な印を入れて実データを読む（読んだら戻す） |
| `paste.js` | 1ページ種別を流し込んで保存し、読み直して突き合わせる |
| `paste-all.js` | 全ページ共通＋11ページ種別をまとめて |
| `modules.js` | モジュール6件（IDの確認と書き込み） |
| `preview.js` | 「プレビュー」を押して、配信されるHTMLを保存する |
| `verify.js` | 配信されたHTMLを点検する |
| `parity.js` | 現行サイトの文言が出ているかを突き合わせる |
| `diff.js` `module-diff.js` | 保存されている中身と手元のファイルの差を見る |
| `goto.js` `eval.js` `open.js` | 画面を開く・式を評価する（下調べ用） |

## つまずいたところ

**プレビューのURLを開くだけでは古いものが返ります。** HTMLは
`プレビュー` ボタンを押した瞬間に焼き付けられます。`preview.js` は毎回押します。

**プレビューは「保存済みの内容」を描きます。** `formPreview` に流し込んだ
HTMLは使われません（印が1つも出ませんでした）。`probe.js` は
いったん保存 → 読む → **元に戻す** の順でやります。

**ポップアップは開きません。** 人が押していないフォーム送信なので止められます。
`target` を `_self` にしてから押します。送る中身は変わりません。

**モジュールの中からモジュールは呼べません。** `<{$module.calendar1}>` を
左メニュー（モジュール）の中に書いても展開されません。エラーも出ません。

**保存の入口は画面ごとに違います。**

```
ページ種別  g_editor_object["html_pc"]   →  saveContent()
モジュール  textarea[name=content] の CodeMirror  →  updateModule()
```

**文字数だけで一致を判断できません。** サーバーは保存時に一部の文字を
数値参照にします（`—`→`&#8212;`、`🔴`→`&#128308;`）。しかも元ファイル自体が
`&#12316;` `&#169;` を持っています。**両側に同じ処理をかけてから**比べます。
